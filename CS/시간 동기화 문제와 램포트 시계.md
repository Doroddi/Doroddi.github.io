## 램포트 논리 시계
분산시스템에서 힘들게 절대 시각을 계산해서 구할 필요가 없음.  
이중화된 데이터베이스 문제는 절대 시각을 구하지 못해서 발생한 문제가 아니라 어떤 두 연산의 순서에 대한 합의를 이루지 못해서 발생한 문제.  
정확한 시각을 몰라도 선후관계만 알 수 있으면 충분함.  

램포트 시계는 모든 장치가 각자 자신의 램포트 논리 시계 Ci를 갖는다고 가정함.  
이 값은 각 장치가 시작할 때 0으로 초기화되며, 램포트 논리 시계의 값은 정수 값으로 각 장치가 특별한 이벤트를 실행하기 전에 자신의 시각을 1 증가시킴.  
만약 한 장치가 다른 장치로 메세지를 보내는 경우, 메세지를 보내는 장치는 자신의 램포트 시각을 함께 전송함. 메시지를 받는 장치는 자신의 램포트 시각과 메시지를 수신할 때 받은 상대방의 램포트 시각을 비교하여 더 큰 램포트 시각 값에 1을 더해서 자신의 수신 이벤트에 대한 시각으로 간주함.  
어떤 두 이벤트에 대해, 두 이벤트의 선후관계가 명확하면 A > B로 표기.  
만약 두 이벤트에 대해, 선후관계가 명확하지 않으면 A || B로 표기.

이벤트의 선후관계를 판별하는 방법  
1. 램포트 시각이 더 큰 이벤트가 나중에 발생한 이벤트.
2. 램포트 시각이 같다면 장치의 프로세스 아이디가 더 큰 이벤트가 나중에 발생한 이벤트.

이를 통해 각 이벤트가 발생한 선후 관계를 위에서 정의한 기호로 나타내면,  
( C(a) || C(d) ) > C(b) > C(c)

이를 해석하면 a, d 이벤트는 선후 관계를 파악할 수 없지만, b, c 이벤트는 a, d 이벤트 이후에 일어났다고 간주함.

## 데이터베이스 복제 알고리즘
램포트 논리 시계를 활용해서 이중화된 데이터베이스 문제를 해결하는 데이터베이스 복제 알고리즘.  
1. 데이터베이스를 업데이트해야 하는 작업이 발생하면, 해당 작업을 자신과 다른 DB로 전송함.
2. 작업을 다른 DB로부터 수신했다면 해당 작업을 큐에 저장하는데, 큐에는 반드시 램포트 시각 순으로 저장. 또한 이때 해당 작업이 큐의 맨 앞에 있다면 수신 확인 메시지를 회신함.
3. 업데이트 할 일에 대해 수신 확인 메세지를 받으면, 해당 작업이 다른 지점에서도 확인되었다고 체크함.
4. 체크한 작업은 큐의 가장 첫 뻔째자리에서 제거하고, 해당 작업을 수행함.

**이 알고리즘도 완벽하지는 않음. 메세지가 전송 중 유실되는 케이스, 중간에 서버가 죽는 케이스, 메세지가 위변조된 케이스 등 다양한 장애 상황을 고려하지 않았기 때문.**
