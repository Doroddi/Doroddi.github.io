### 12. [Easy] Kth Largest Element In A Stream (X) [✓]
(https://leetcode.com/problems/kth-largest-element-in-a-stream/)

못 푼 이유: PriorityQueue에 대한 응용도 부족.  
pq는 우선순위가 높은 애가 트리에 루트에 놓이므로 배열에 있는 수와 추가되는 수를 넣기만 하면 우선순위에따라 정렬을 할 수 있음. 배열에 수를 추가할 때보다 연산이 적은 이유는 배열은 n개의 수가 자기 자리를 찾은 후(logn), 수를 미는 동작을 하므로 n*(n+logn)=n^2이 필요함. 하지만 pq는 힙을 정리하는 연산만 존재하므로 nlogn으로 해결됨. 근데 해당 문제에서는 add 연산 시에 수를 pq에 넣는 행위는 logn이지만 k번째 수를 찾는데 k, 이 동작을 add 함수 호출 만큼 실행하므로, klogn*(add 함수 호출)로 최악의 경우 10^8 이상이 됨. 따라서 k번째 수를 더 빠르게 찾는 방법을 도출해내야할 것 같은데 가지치기로는 어림도 없었음.  
+) 핵심 아이디어는 pq에 k개의 수만 저장하면 루트에 k번째로 큰 수를 저장할 수 있다는 것. 그렇게 되면 찾는 비용이 1이되므로 logk*(add 함수 호출)로 연산이 줄어듦. 그럼 처음 배열을 pq에 추가하는 비용까지 합치면 전체 시간복잡도는 O((n+m(add))logk)임.
